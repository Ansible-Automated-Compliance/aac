= AAC on Existing AAP — Production-Oriented Install Guide
:toc: left
:toclevels: 3
:sectanchors:
:sectnums:

Estimated time: 2 to 4 hours for a careful first install.

== What you get

- OPA containers (`opa-security`, `opa-compliance`, `opa-ot`)
- REGO policies loaded from the `policies/` submodule
- A *dedicated* AAC PostgreSQL database
- Grafana dashboards
- An AAP project + job templates
- An Execution Environment

== Architecture recommendation

Prefer a dedicated AAC host to provide clear blast radius, capacity, and naming. Do not risk AAP data or container names. The EDA and MCP configurations are optional for a first production cut.

== Prerequisites

- AAP *2.5.5* or later
- RHEL for `aac_host`
- Outbound HTTPS to GitHub, console.redhat.com, and registry.redhat.io
- Firewall capacity for AAC ports

== AAC Host setup

=== Basic requirements

RHEL server with `compliance` user, registered to Red Hat.

[source,bash]
----
ssh compliance@<aac-host>
echo "compliance ALL=(ALL) NOPASSWD: ALL" | sudo tee /etc/sudoers.d/compliance
sudo dnf install -y podman ansible-core vim tree jq curl pip bash-completion
sudo dnf upgrade -y && sudo systemctl reboot
mkdir ~/repos/
----

=== Repository checkout

[source,bash]
----
cd ~/repos/
# Pick one — HTTPS or SSH:
# git clone https://github.com/ansible-automated-compliance/aac.git
git clone https://github.com/ansible-automated-compliance/aac.git
cd compliance
git submodule update --init --recursive
tree -L 2 policies/benchmarks/
----

You might have to generate and register SSH key with GitHub.

[source,bash]
----
ssh-keygen -t ed25519 -C "compliance@<aac-host>"
cat ~/.ssh/id_ed25519.pub
----

Add the public key to GitHub.

== Secrets setup

Make a copy of the example secrets file and edit the PLACEHOLDERs. Never commit real secrets.

[source,bash]
----
cp ansible/vars/vault_secrets.yml.example ansible/vars/vault_secrets.yml
----

NOTE: Credentials are *not* inherited by all templates in a project — attach them per job template.

[source,bash]
----
vim ansible/vars/vault_secrets.yml
----

[source,yaml]
----
---
# CATEGORY 1 — MUST PROVIDE (personal credentials — unique per installer)
vault_redhat_username: some_username
vault_redhat_offline_token: PLACEHOLDER_paste_your_offline_token_here
vault_github_pat: ghp_PLACEHOLDER_paste_your_pat_here
vault_quay_username: some_username
vault_quay_password: some_password

# CATEGORY 4 — MUST SET
vault_aap_admin_password: CHANGE_ME

# CATEGORY 5 — CAN USE DEFAULTS
compliance_db_password: compliance
compliance_reader_password: compliance
grafana_admin_password: <grafana-admin-password>

# CATEGORY 6 — CAA
caa_signing_private_key: |
  # Paste the ENTIRE contents of your cosign.key here as an indented
  # block scalar, including its BEGIN/END header and footer lines.
  # Generate one with: cosign generate-key-pair
caa_signing_password: ""
----

=== CAA signing key (required for CIS playbooks that enable CAA)

Generate keys using the cosign binary from a container.

[source,bash]
----
cid=$(podman create registry.access.redhat.com/hi/cosign:3)
podman cp "$cid":/usr/bin/cosign ./cosign
podman rm "$cid"
chmod +x ./cosign
COSIGN_PASSWORD="" ./cosign generate-key-pair
----

IMPORTANT: The *public* key is for auditors (`cosign verify-blob`); do *not* inject it as the signing secret on the template.

=== Encrypt vault_secrets.yml

[source,bash]
----
ansible-vault encrypt ansible/vars/vault_secrets.yml
----

=== Container secrets (podman)

Create podman secrets so passwords never appear in `podman run` commands or process listings.

[source,bash]
----
podman secret list
printf 'compliance' | podman secret create compliance_db_password -
printf 'compliance' | podman secret create compliance_reader_password -
printf '<grafana-admin-password>' | podman secret create grafana_admin_password -
podman secret list
----

To rotate a secret later:

[source,bash]
----
podman secret rm compliance_db_password
printf 'new_password' | podman secret create compliance_db_password -
----

== OPA installation

=== Prerequisites

First, lets create the `/opt/opa/compliance` and `/etc/opa` directories and set the correct permissions.

[source,bash]
----
sudo mkdir -p /opt/opa/compliance /etc/opa
sudo chown -R compliance:compliance /opt/opa/compliance /etc/opa
----

=== OPA Containers installation

Now run the installation playbook

[source,bash]
----
ansible-playbook -J ansible/playbooks/deploy_opa_containers.yml \
  -e "aac_host=<aac-host>" -e "become_user=root" \
  -e "become=true" -e "become_method=sudo"
----

Verify:

[source,bash]
----
curl -s http://<aac-host>:8181/health
curl -s http://<aac-host>:8182/health
curl -s http://<aac-host>:8183/health
# Expect HTTP 200 / JSON health
----

=== PostgreSQL installation

[source,bash]
----
podman volume create compliance_pgdata

podman run -d --name aac-postgresql \
  -p 5432:5432 \
  -e POSTGRESQL_USER=compliance \
  -e POSTGRESQL_DATABASE=compliance \
  --secret compliance_db_password,type=env,target=POSTGRESQL_PASSWORD \
  -v compliance_pgdata:/var/lib/pgsql/data \
  --restart=always \
  registry.redhat.io/rhel9/postgresql-15:latest
----

Now initialize the database without using the EE container.

Install the dependencies 

[source,bash]
----
pip3 install --user psycopg2-binary
ansible-galaxy collection install community.postgresql
----

[source,bash]
----
ansible-playbook -J ansible/playbooks/postgres_database_init.yml \
  -e "aac_host=<aac-host>" \
  -e "pg_host=<aac-host>" \
  -e "pg_user=compliance" \
  -e "aac_db_container_name=aac-postgresql" \
  -e "aac_db_skip_container_deploy=true"
----

NOTE: The error in TASK `[aac_compliance_db : Create compliance_reader role]` is expected and can be ignored.

Verify:

=== Grafana installation

Install Grafana

[source,bash]
----
podman volume create compliance_grafanadata
podman run -d --name aac-grafana \
  --network=host \
  --restart=always \
  -v compliance_grafanadata:/var/lib/grafana \
  -e GF_SECURITY_ADMIN_USER=admin \
  --secret grafana_admin_password,type=env,target=GF_SECURITY_ADMIN_PASSWORD \
  -e GF_SERVER_HTTP_ADDR=0.0.0.0 \
  -e GF_SERVER_PORT=3000 \
  -e GF_SERVER_ROOT_URL=http://<aac-host>:3000 \
  -e GF_INSTALL_PLUGINS=grafana-postgresql-datasource \
  registry.redhat.io/rhel9/grafana:latest
----

TIP: `GF_SECURITY_ADMIN_PASSWORD` only takes effect on first-time initialisation against an empty database. If you re-create the container and authentication fails, delete the volume first: `podman volume rm compliance_grafanadata && podman volume create compliance_grafanadata`.

Verify:

[source,bash]
----
curl -s http://<aac-host>:3000/api/health
----

NOTE: `ansible/playbooks/deploy_grafana_dashboard.yml` does *not* start Grafana. It only configures the datasource + imports dashboards against an *existing* Grafana on `:3000`.

[source,bash]
----
ansible-playbook -J ansible/playbooks/deploy_grafana_dashboard.yml \
  -e "grafana_url=http://<aac-host>:3000" \
  -e "pg_host=<aac-host>"
----

=== Quadlets

Turn off the broken system units (as root once only)

[source,bash]
----
sudo systemctl disable --now container-opa-security.service \
  container-opa-compliance.service container-opa-ot.service

sudo rm -f /etc/systemd/system/container-opa-*.service \
  /etc/systemd/system/container-aac-postgresql.service \
  /etc/systemd/system/container-aac-grafana.service

sudo systemctl daemon-reload
----

As compliance — generate Quadlets for containers

[source,bash]
----
mkdir -p ~/.config/containers/systemd/
cd ~/.config/containers/systemd/
----

Copy the files in the quadlets directory to the systemd directory

Remove the hand-started containers so Quadlet owns them

[source,bash]
----
podman rm -f opa-security opa-compliance opa-ot aac-postgresql aac-grafana
----

Enable on the user bus (no sudo)

[source,bash]
----
systemctl --user daemon-reload
systemctl --user list-unit-files | grep -E 'opa|aac'
systemctl --user start \
  opa-security.service \
  opa-compliance.service \
  opa-ot.service \
  aac-postgresql.service \
  aac-grafana.service
systemctl --user is-active \
  opa-security.service \
  opa-compliance.service \
  opa-ot.service \
  aac-postgresql.service \
  aac-grafana.service
----

Survive logout/reboot without an interactive login

[source,bash]
----
loginctl enable-linger compliance
loginctl show-user compliance -p Linger
systemctl --user --failed
----

=== Testing and Demonstration

==== Verify activations are running

In the AAP UI under *Automation Decisions -> Rulebook Activations*, confirm every activation shows *Running*. If an activation shows *Failed* or *Stopped*, click into it and check the *History* tab for the error. Common causes:

- *Credential mismatch* — the activation must use the `AAP Controller Token` credential, not a machine credential.
- *Port conflict* — another activation (or process) already bound to the same port. Check with `ss -tlnp | grep <port>` on the AAP host.
- *Decision Environment pull failure* — the DE image pull needs the `Red Hat Container Registry` credential attached to the DE definition. Check *Automation Decisions -> Decision Environments*.

== Native AAP Policy as Code

=== Configuration

This section wires the OPA you already run on the AAC host (`<aac-host>`) into *Ansible Automation Platform*'s built-in Policy as Code feature. That is separate from AAC assessment
playbooks: PAC blocks/allows *job launches* in the AAP console *before* the playbook runs.

Reference: Red Hat docs —
https://docs.redhat.com/en/documentation/red_hat_ansible_automation_platform/2.6/integrate-assembly_controller_pac

IMPORTANT: PAC evaluates *job context* (extra_vars, template, inventory, credentials, launching user). It does *not* parse playbook YAML.

==== Step 1 — Point AAP at your OPA server

In the AAP UI go to *Settings* → *Job* / *Policy settings*, Set:

[cols="2,3",options="header"]
|===
| Setting | Value for this install
| OPA Server hostname (`OPA_HOST`) | `<aac-host>`
| OPA server port (`OPA_PORT`) | `8181`
| OPA SSL (`OPA_SSL`) | `False` (HTTP lab)
| OPA authentication type | `None` (lab)
| OPA request timeout | `5` (seconds; default 1.5 is tight on lab links)
| OPA request retry count | `2`
|===

Save.

Verify from the AAP host:

[source,bash]
----
curl -s -o /dev/null -w '%{http_code}\n' http://<aac-host>:8181/health
# Expect 200
----

==== Step 2 - Create a centralized PAC policy repository

At the AAC host, create a directory for PAC policies:

[source,bash]
----
sudo mkdir -p /opt/opa/compliance/policies/pac
sudo chown -R compliance:compliance /opt/opa/compliance/policies/pac
----

==== Step 3 — Create a simple PAC Rego policy

Create a file `hello_aap_pac.rego` in the PAC policy repository:

[source,bash]
----
touch /opt/opa/compliance/policies/pac/hello_aap_pac.rego
----

[source,rego]
----
package hello.aap.pac

import rego.v1

# AAP Policy as Code contract: rule must evaluate to
# { "allowed": bool, "violations": [string] }
default result := {
	"allowed": false,
	"violations": ["hello.aap.pac: evaluation produced no decision"],
}

allowed_envs := {"development", "production"}

violations contains msg if {
	env := object.get(object.get(input, "extra_vars", {}), "environment_cli", "")
	not env in allowed_envs
	msg := sprintf(
		"PAC deny: extra_vars.environment_cli must be one of %v (got %v)",
		[allowed_envs, env],
	)
}

result := {
	"allowed": count(violations) == 0,
	"violations": [v | some v in violations],
}
----

Load it into the security OPA (package path → API path):

[source,bash]
----
curl -X PUT --data-binary @hello_aap_pac.rego \
  http://<aac-host>:8181/v1/policies/hello_aap_pac

# Smoke-test with empty extra_vars → deny
curl -s http://<aac-host>:8181/v1/data/hello/aap/pac/result \
  -H 'Content-Type: application/json' \
  -d '{"input":{"extra_vars":{}}}' | jq .

# Smoke-test with valid extra_vars → allow
curl -s http://<aac-host>:8181/v1/data/hello/aap/pac/result \
  -H 'Content-Type: application/json' \
  -d '{"input":{"extra_vars":{"environment_cli":"development"}}}' | jq .
----

Expect `allowed: false` then `allowed: true`.

The OPA policy name you will type in AAP is `hello.aap.pac/result`

==== Step 6 — Attach the policy (enforcement point)

Edit the job template (or the Organization / Inventory — JT is clearest for a lab):
. Open *Hello AAP — PAC demo*
. Find *OPA policy*
. Enter: `hello.aap.pac/result`

Enforcement levels (any one is enough for the demo):

* *Job template* — only this template
* *Inventory* — every job using that inventory
* *Organization* — every template in the org (broad; avoid for first test)
If no resource has an OPA policy set, AAP will not call OPA.

==== Step 7 — Prove deny, then allow

*Deny (missing / invalid environment_cli):*
. Launch *Hello AAP — PAC demo* with no extra vars
  (or `-e environment_cli=staging`).
. Expect the job to be *blocked before playbook start*, with a
  violation message from Rego (similar to
  `PAC deny: extra_vars.environment_cli must be one of ...`).

*Allow:*
. Launch again with Extra Variables:
[source,yaml]
----
environment_cli: development
----
. Expect PAC to allow; the job proceeds to normal Ansible execution
  (SSH / firewalld / httpd as in hello-aap).
