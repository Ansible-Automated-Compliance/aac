# Collectors

AAC collects through Ansible. Anything an Ansible module or `gather_facts` can read, AAC can collect, store and evaluate with a policy. This page lists the collectors that ship in this repository: what each one gathers from, how it gathers the facts and where they are stored.

A target that is not in the table has no collector shipped yet. That does not mean it cannot be collected: use the Ansible module that reads it, send the result to the policy, and [ask for it to be added](https://github.com/Ansible-Automated-Compliance/aac/issues/new/choose).

## Where the collectors live

The code stays where Ansible and the job templates expect it. This directory is the index.

| Place | What is there |
|---|---|
| `ansible/playbooks/` | Assessment and collection playbooks |
| `ansible/tasks/` | Collection task files shared by playbooks |
| `ansible/roles/aac_facts_collector/` | The nightly fact collector for Linux, Windows and AWS |
| `collections/ansible_collections/aac/` | The `aac.m365` and `aac.host_facts` collections |
| `extensions/eda/` | Event-Driven Ansible sources and rulebooks |

## Change the list

The table is generated from [`catalog.yml`](catalog.yml). Do not edit it by hand.

```bash
python3 scripts/collector_catalog.py --write   # regenerate the table
python3 scripts/collector_catalog.py --check   # what CI runs
```

When you add a collector, add its entry to `catalog.yml` in the same pull request. The check fails if a playbook, task file, module or role that looks like a collector is not listed. If the file is not a collector, list it under `not_collectors` with the reason.
